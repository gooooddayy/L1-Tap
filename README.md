# L1-Tap（连点器）

Android 悬浮窗连点器工具。两个悬浮钮（⚙ 设置/停止钮 48dp + ◎ 靶标 24dp），把靶标拖到目标位置，设置参数后自动连点。

- **包名**：`com.l1.autoclicker`
- **最低支持**：Android 7.0（minSdk 24）——核心点击 API `dispatchGesture` 是 API 24 引入的，6.0 无法支持
- **体积**：~42KB，零联网、零第三方库、无 so 库
- **构建**：无 Gradle，`build.sh` 七步流水线（aapt2 → javac → d8 → zipalign → apksigner）

## 功能与参数模型

| 参数 | 含义 | 默认 |
|---|---|---|
| 连点时间 | 点击持续的时长（秒），1~3600 | 30 |
| 连点频次 | 持续时间内的点击总次数（正整数） | 10 |
| 循环轮次 | 循环的轮数，0 = 只跑一轮 | 0 |

核心换算：**间隔 = 连点时间 × 1000 ÷ 连点频次**（默认 30s/10次 = 每 3 秒点 1 次）。两次点击最小间隔 50ms（面板强制校验）。

## 交互设计

- **待命态**：两钮可随意拖动；点 ⚙ 进设置页；设置页右上角「退出悬浮控件」= 彻底退出；「开始」下方「返回」= 仅关面板、悬浮钮保留
- **执行态**：⚙ 变红 ■（一碰即停）；靶标 `FLAG_NOT_TOUCHABLE` 只显示不拦截（触摸穿透到下层应用，不影响正常操作）；屏幕常亮；面板关闭
- **设置页**：实时换算摘要；总时长 >10 分钟需二次确认

## 停止通道（安全第一，任何一条可用即可停）

| 类别 | 通道 | 机制 |
|---|---|---|
| 用户主动 | 摸屏幕任意位置 | 设置窗 `FLAG_WATCH_OUTSIDE_TOUCH` 旁听 ACTION_OUTSIDE |
| 用户主动 | 点红钮 | 红钮 DOWN 无条件停止（自身连点不会落进本窗口） |
| 用户主动 | 通知栏「停止」 | 前台服务 Action，完全不依赖悬浮窗 |
| 环境被动 | 靶标内容/应用变化 | 每 500ms 采样前台包名+方向+落点控件特征，与锚点比对 |
| 环境被动 | 息屏 | ACTION_SCREEN_OFF 广播 |
| 环境被动 | 轮次跑完 | 自然结束 |
| 异常兜底 | 连续派发失败 ≥10 次 | 熔断自动停 |

## 权限（最小集，均为功能硬依赖）

`SYSTEM_ALERT_WINDOW`（悬浮窗）· `FOREGROUND_SERVICE` + `FOREGROUND_SERVICE_SPECIAL_USE`（前台服务）· `POST_NOTIFICATIONS`（13+ 通知栏停止按钮）

## 构建指南

```bash
bash build.sh   # 产物 out/AutoClicker-v1.4.apk
```

环境依赖：JDK 11+、Android SDK build-tools 33+（脚本内 `BT`/`JB` 变量指向本机路径，克隆后按需修改）。

### ⚠️ 签名说明（重要）

公开仓库**不含** `keystore/app.jks`（真实签名密钥），它单独存放在私有仓库 **`gooooddayy/L1-Tap-sign`**。

- 直接克隆本仓库构建：脚本检测不到 keystore 会**自动生成新签名**——功能正常，但**无法覆盖升级**已安装的正式版（签名不同）
- 要发可覆盖升级的正式版：从私有仓库把 `app.jks` 放回 `keystore/` 目录再构建
- 签名密码在 build.sh 的 `PASS` 变量（keystore 本身是秘密，密码不含敏感信息）

### 覆盖升级的硬约束

- `versionCode` 必须严格递增，**不跳号、不重置**
- 签名必须用同一个 keystore
- APK 命名：`AutoClicker-v<版本>.apk`，产物放 `out/`

## 开发排错

关键日志 TAG：`AutoClicker`、`TapService`。

```bash
adb logcat -d | grep -E "AutoClicker|TapService" | grep -v SystemUi
```

启动参数、锁点坐标、锚点采样、靶标变化详情、手势派发失败、engine-end 原因全有埋点，问题秒级定位。
