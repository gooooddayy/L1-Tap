# L1Tap 全版本审查：触摸停止根因与重构方案

> 审查范围：v1.0.0（正常基线）→ aa → ab → ac → ad → ae → af → ag → ah
> 方法：逐版本源码/构建物哈希对比 + 真机日志逐事件取证（logcat 存档于 out/）
> 结论一句话：**「触摸停止」前后五轮修复全部在同一个错误前提下打转——"能区分真手与自身注入"。而本 ROM 的触摸副本天生不可判别，这条路走不通。必须换成"几何判别"架构。**

---

## 二、核心取证：ColorOS 触摸事件的"护照"（全部实测）

| 事件 | flags | toolType | eventId | 坐标 | 证据出处 |
|---|---|---|---|---|---|
| 真手 → 应用（直投） | 0x800~0x802 | **FINGER** | **正数** | 真实位置 | 19:55:26.285 netease 收到 (1127.26,2543.32) |
| 自身注入 → 应用（直投） | 0x801 | UNKNOWN | **负数** | 真实位置(=落点) | 19:55:25.550 netease 收到 (1139.0,2549.0) |
| 自身注入 → 自家靶窗（自伤） | 0x800 | UNKNOWN | 负数 | (42,42)=靶窗中心 | 19:54:14.206 等 6 处（AH 期） |
| **系统 ACTION_OUTSIDE 副本**（无论源头） | 不可见/不可复原 | 不可见 | 不可见 | **不可复原** | 见下 |

**副本不可判别的三条铁证：**
1. **ad 期实停反证副本存在**：17:54:55.466 outside 停止，用户触摸在目标点 10px 内（netcase 侧 55.588 收到 FINGER UP）。若副本坐标可复原，±16dp 豁免必命中→不应停；它停了 → **副本坐标 ≠ 真实触摸位置**。
2. **af 期自停反证**：自家注入的副本（+1.003s 锁相）双语义坐标检查全部落空 → ±80dp 豁免形同虚设 → 自停。
3. **ag/ah 期 26 个会话 0 次触发**：副本仍存在（投递链路被 af 证明通畅），但被 `flags&0x800` 过滤全部吞掉——**真手副本也带 0x800**（副本由系统合成，旗标/工具类型/坐标三个可观测维度全部"串味"，与源头无关）。

## 三、根因结论（三层叠加）

| # | 根因 | 说明 | 证据 |
|---|---|---|---|
| RC1 | **副本无国籍** | 真手与注入的 outside 副本在全部可观测维度上同签名；任何"旗标/工具类型/坐标"判别在本 ROM 都不可能成立 | 上表 + 铁证 1/2/3 |
| RC2 | **ad 的可用性靠"时间接近度"兜底** | 自家副本总在派发后 ≤150ms 到达（被时间窗豁免），真手副本随机（放行）。af 删掉时间窗 → 自伤；ag/ah 改用旗标过滤 → 真手副本也被吞 → **通道彻底死亡** | af/ag/ah 日志 |
| RC3 | **环层从未接到触摸（几何原因）** | 环内孔 ±22dp=77px 太大；用户实测触摸全部集中在点击点 6~21px 内（"点靶控件"）→ 全部从孔内穿透，环层根本没机会触发——不是坏的，是**从没碰到** | 55:10.343/11.744/12.992 三次靶点触摸直达 netease |
| RC4 | **首击自伤（本次新发现）** | 靶窗 NOT_TOUCHABLE 的 WM 生效有延迟，**首击有时落在自家靶窗被吞**（日志 6/8 会话出现 (42,42) 自伤事件）→ 每次开跑可能少点 1 次 | 19:54:14.206、55:24.571 等 |

**附：侧滑的真相**（不变）：ColorOS 系统层独占侧滑手势，应用只能靠"恰有在途点击被取消"感知（cancel 通道）——这就是"侧滑有时能停"的全部来源。

## 四、重构方案 v2：「海绵层」几何判别（1.0.0ai）

**不再依赖副本通道**。执行期把屏幕用触摸"海绵"覆盖起来，只留点击点一个小孔——**摸到海绵的任何一点 = 100% 是用户（因为自动点击只可能从孔里穿过）**，无需任何猜测。

### 设计
1. **海绵层**：4 块可触摸矩形覆盖全屏（上/下/左/右），点击点周围仅留 **±2dp（本机 ±7px）** 方孔；窗口标志 = NOT_FOCUSABLE | **NOT_TOUCH_MODAL（修正旧环层缺失）** | LAYOUT_IN_SCREEN。
2. **行为**：
   - DOWN 落在点击点 80dp 内 → 拖动模式（超 slop 即停+拖靶换位；原地轻点→停）
   - DOWN 落在其他任何位置 → **立即停（DOWN 即停，快于现在所有通道）**
   - 手指在屏时延迟拆层（复用现有机制）
3. **删除**：整个 ACTION_OUTSIDE 分支 + WATCH_OUTSIDE 标志 + 全部（旗标/工具类型/坐标）判别——本 ROM 上无意义，留着只会再犯。
4. **保留**：cancel 通道（侧滑唯一信号）、红钮、通知栏、息屏、250ms 采样、引擎与看门狗。
5. **首击自伤修复**：首击延迟 ~120ms 再派发（一次性，不影响节奏）。
6. **诊断日志**：海绵 DOWN/UP 坐标、自伤事件、几何自检（海绵矩形坐标+落点一并记录）——下轮实测一次即可验证。
7. 版本 1.0.0ai / vc14。孔大小、80dp 带、120ms 均可调。

### 覆盖效果对比
| 通道 | 现在(ah) | 海绵版 |
|---|---|---|
| 点靶标周边（±80dp 带外沿~内沿） | 无（环洞 77px） | **停**（孔仅 ±7px） |
| 点靶标正中 ±21px（用户实测分布） | 无 | 6 处中 5 处停，仅 ≤7px 盲 |
| 屏幕其他地方 | 0 触发 | **立即停** |
| 拖动靶标 | 停+换位 | 停+换位（保持） |
| 侧滑 | 在途时 cancel 停 | 同（不变） |

### 已知边界（诚实告知）
- 点击点正中 **±2dp**（指甲尖大小）为唯一盲区——自动点击本体必须从这走，物理不可区分。
- **停止的那一次触摸会被海绵接住、不传给下层应用**（想继续操作需再摸一次）。可后续升级"手势重放"（把接住的点击还给下层），先不做。
- 状态栏下拉区属系统窗口（海绵之上），摸它不停——红钮/通知栏仍是兜底。
- 侧滑：系统层优先（不变）。

## 五、实施与验证清单

**改动**：OverlayService（海绵层替换环层；删 outside 通道；首击延迟；日志）→ build.sh 升 1.0.0ai/vc14 → 构建装机。

**测试重点**：
1. 摸屏幕各处（含靶标四周 / 屏幕中部 / 底部）→ 每次必须立即停（各 3 次）；
2. 拖靶标 → 停+换位，下轮点新位置；
3. 跑完 5 击自然结束，**不再少点**（首击自伤修复）；
4. 回归：红钮 / 通知栏 / 侧滑（在途时）/ 靶标变化采样；
5. 已知边界复核：正压靶心 ±7px 内不停属预期。
