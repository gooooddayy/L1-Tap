# L1Tap v1.0.0aq（vc22）——本轮验证：无障碍列表「找不到 L1Tap」的根因与处置

> 反馈：无障碍列表里总要把应用开一会儿、有时反复进退两次才看得到 L1Tap。
> 真机定位（PJE110 / ColorOS 14 / Android 14）：**不是权限列表刷新慢，是手机把应用「速冻」了**。
> 速冻 = 把整个包置为 `COMPONENT_ENABLED_STATE_DISABLED`（`pm disable`）。被禁用的包不参与 intent 解析，
> `queryIntentServices` 扫不到 → `AccessibilityManagerService.mInstalledServices` 里没有 TapService →
> 设置的「已下载的应用」里根本没有这个条目。打开一次应用即自动解冻，系统重扫后条目才出现。

## 一、实测证据（同一台机，间隔数秒）

| 观测点 | 打开应用前 | `am start` 打开一次后 |
|---|---|---|
| `pm list packages -d` | **含 com.l1.autoclicker** | 不含 |
| 包状态 | `enabled=2`(DISABLED) `stopped=true` | `enabled=1`(ENABLED) `stopped=false` |
| `query-services -a ...AccessibilityService` | 21 个服务，**无 L1Tap** | 出现 `com.l1.autoclicker/.TapService` |
| `dumpsys accessibility` installedServiceCount | **20** | **21** |

- 该机 disabled 包共 33 个（含 GMS、多家银行）→ 符合 ColorOS 应用速冻特征。
- `pm enable` / `cmd package enable` 被 ROM 拦（`SecurityException: Shell cannot change component state for null to 1`），只有启动应用（点图标 / `am start`）能解冻。

## 二、本轮改动

1. 主界面无障碍卡改为三态 + 一行提示：
   - `✔ 已开启`
   - `✘ 未开启` → 提示「点右侧『去开启』→ 无障碍 → 已下载的应用 → L1Tap → 打开开关」
   - `⚠ 系统待刷新` → 系统已装上但尚未收录进无障碍列表（刚解冻的 1~2 秒窗口），提示稍等；3s 自动重检，最多 12 次
2. 使用说明新增「无障碍列表里找不到 L1Tap？」排障两条（打开一次应用解冻 / 关掉应用速冻）。
3. **未改清单**：`exported="false"` 实测不影响收录与绑定（解冻后立即被收录，历史版本一直能正常绑定）。
4. **未用详情页深链**：`android.settings.ACCESSIBILITY_DETAILS_SETTINGS` 对应 Activity 受签名权限
   `OPEN_ACCESSIBILITY_DETAILS_SETTINGS` 保护，三方应用调用必抛 SecurityException（adb 实测）。

## 三、测试清单

| # | 操作 | 预期 |
|---|---|---|
| 1 | 打开 L1Tap | 无障碍卡显示 `✘ 未开启` + 进入路径提示（系统已收录本服务时） |
| 2 | 点「去开启」 | 进系统无障碍页，二级入口「已下载的应用」里能看到 L1Tap 自动点击服务 |
| 3 | 打开开关后返回 L1Tap | 卡片变 `✔ 已开启`，「启动悬浮控件」可点 |
| 4 | 放置数天不用后再打开 | 若被速冻：主界面能正常启动并自动解冻，无障碍卡最多 1~2 秒内从 `⚠ 系统待刷新` 变 `✘ 未开启` |
| 5 | 关闭 L1Tap 后进无障碍列表 | 条目仍在（不再需要「进两次」） |

## 四、永久解法（用户侧一次性）

设置 → 电池 → 应用速冻 → 关掉 L1Tap（设置里搜「速冻」最快）。关掉后不会再被冻结，列表里也不会再消失。
