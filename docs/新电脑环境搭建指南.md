# L1-Tap 新电脑环境搭建指南

> 目标：在新电脑上从零开始，仅凭本仓库 + 私钥仓库，恢复「改码 → 构建 → 签名 → 装机」全流程。
> 本文写于 2026-10-14（v1.0.0ap / vc21 迁移时），路径以旧机为准，新机按需调整。

## 一、需要安装的东西

| 组件 | 旧机版本 | 用途 | 获取方式 |
|---|---|---|---|
| Git Bash | 任意 | 跑 `build.sh`（依赖 cygpath） | git-scm.com |
| JDK | Android Studio 自带 JBR（javac --release 17） | 编译 | 装 Android Studio 或单独 JDK 17+ |
| Android SDK build-tools | **36.0.0**（aapt2/d8/zipalign/apksigner） | 构建 | Android Studio → SDK Manager |
| Android SDK platform | **android-37.0**（android.jar） | 编译 classpath | SDK Manager（新机装可用版本即可，改 build.sh 对应路径） |
| adb platform-tools | 最新 | 装机/抓日志 | developer.android.com/studio/releases/platform-tools |
| Python 3 | 任意（仅用于往 APK 里塞 classes.dex） | 构建第 6 步 | python.org |

## 二、拿到代码与密钥

```bash
# 公开仓库（源码+文档）
git clone https://github.com/gooooddayy/L1-Tap.git
# 私钥仓库（签名密钥，需要你的账号 token / 登录）
git clone https://github.com/gooooddayy/L1-Tap-sign.git
# 把 app.jks 放到 L1-Tap/keystore/app.jks（build.sh 会自动检测，不存在会生成新钥——千万别让它生成，否则无法覆盖升级！）
cp L1-Tap-sign/app.jks L1-Tap/keystore/app.jks
```

**签名要素**（丢失 = 永远无法覆盖升级，务必自存一份密码管理器）：
- 密钥库：`keystore/app.jks`（alias `l1key`，RSA 2048，有效期 30 年）
- 密码：`build.sh` 第 10 行 `PASS` 变量（storepass = keypass 同值）

## 三、build.sh 需要按新机路径改的地方（前 11 行）

```bash
SDK="/c/Users/Administrator/AppData/Local/Android/Sdk"   # ← 新机 SDK 路径
BT="$SDK/build-tools/36.0.0"                             # ← 新机 build-tools 版本
AJ="$SDK/platforms/android-37.0/android.jar"             # ← 新机 platform 版本
JB="/d/Android Studio/jbr/bin"                           # ← 新机 JDK bin 路径
PASS="l1pass123"                                         # 签名密码（与私钥仓库配套）
PY="…/python.exe"                                        # ← 新机 Python 路径
```

## 四、构建与装机

```bash
bash build.sh                    # 产物 out/L1Tap-v<版本>.apk，输出必须 grep 到 BUILD_OK
adb install -r out/L1Tap-*.apk   # 装机（重装后无障碍开关会掉，需手动重开）
adb logcat -d -s AutoClicker:* TapService:*   # 抓日志（两个 tag 都要，漏 TapService 会漏引擎日志）
```

改版本号两处：`build.sh` 第 29 行（--version-code/--version-name）+ 第 54 行（OUT 文件名）+ `app/build.gradle` 的 versionCode/versionName。
版本规范：基线 1.0.0，小更新双字母后缀 aa→ab→…，versionCode 严格递增。

## 六、新机必读的三条架构事实（不看会重蹈覆辙）

1. **ColorOS 的 ACTION_OUTSIDE 副本坐标/旗标/工具类型全部不可复原**，真手与注入同签名——
   任何「旁听+判别触摸」路线物理不可行（aa~ah 五轮全部折在此），触摸停止靠**海绵层几何判别**（ai 起）。
2. **overlay 窗口的 lp.x/y 是申请值不是实际值**：ColorOS 默认 insets fit 会把顶部窗口下移状态栏
   高度盖住小孔（ak 定案）。所有 overlay 已统一 `noFit()`；做像素级几何必须运行时
   `getLocationOnScreen` 对账。
3. **采样通道区分「自更新」与「控件更换」**：点赞/计数类控件文本随成功点击刷新（ap 定案），
   sig 比对比的是类名+ID（控件身份），不是文本/bounds（状态）。

## 七、发布流程（GitHub REST API）

本机 git 协议连不上 github.com 时，用 token 走 API：
- 多文件提交：`POST /repos/gooooddayy/L1-Tap/git/trees`（base_tree + content）→ commits → PATCH ref
- Release 资产：`uploads.github.com` 上传，tag 保持 v1.0.0，资产名 `L1Tap-v<版本>.apk`
- 私钥/私有仓核对用账号 token 直连 api.github.com
